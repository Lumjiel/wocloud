# tools/ — 批量备份 / 目录治理工具

## wocloud-bulk.mjs

绕开 CLI `push` 缺陷的批量备份工具。零依赖，Node 18+。

## 为什么不用 push

`push` 把「建目录」和「传文件」混在一个循环里，而服务端对 `CreateDirectory` 有**未公开的频率限制**（密集调用时返回 `RSP_DESC: "系统异常"`）。目录建失败时 push 静默降级：

```js
// push 实现节选
const id = res?.RSP?.DATA?.id;
if (id) dirMap.set(rel, id);
else console.error(`✗ 建目录失败: ${rel}`);   // ← 只打一行日志，不中断

// 上传阶段
dirId: dirMap.get(父路径) ?? targetId          // ← 查不到就丢到根目录
```

**后果链条：**

1. 建目录失败
2. 该目录下**所有文件被上传到目标根目录**，只有一行 stderr 日志
3. **级联放大**：若 `A/B` 建失败，则 `A/B/C` 查父目录也失败 → **在根目录凭空建出 `C`**

实测一次 `push` 552 个文件：**正确落位约 230、错位到根目录 279、完全未传约 70**，全程无报错。

## 根因验证（证据）

| 实验 | 结果 | 结论 |
|---|---|---|
| 手动建一个「失败」的目录（间隔久） | `RSP_CODE 0000` 成功 | **排除**命名 / 权限 / 路径问题 |
| 间隔 **1.5s** 连建 6 个目录 | 6/6 成功 | 确认是**请求密度**限制 |
| `push` 毫秒级连发 | 前 30 个成功，之后全部「系统异常」 | 阈值很低 |
| 目录**已存在**时重跑 push | 照样大批「系统异常」 | **限流与目录是否存在无关** |
| 批量删 6 个目录 | `500 internal server error` | 同一机制作用于写接口 |
| 逐个删（间隔 1.2s） | 全部成功 | 同上 |
| 同一文件传到**不同目录** | 真实上传（1.46s），**未**被秒传跳过 | 秒传按「目标目录 + 哈希」判定，不影响补传 |

## 设计：三个阶段，绕开一体化流程

```
阶段 1  补齐目录   以 1.8s 节流逐个建（实测 0 失败），记录 路径 → id 映射
阶段 2  直传文件   用已知目录 id 调 upload，全程不再触碰 CreateDirectory
阶段 3  清理残留   删除云端根级中「本地根级没有的」条目
```

**为什么阶段 2 可行**：秒传不阻止同一文件落到不同目录，所以不必先删错位文件，直接补传即可。

## 用法

```bash
# 备份（扫描 → 补目录 → 直传）
node tools/wocloud-bulk.mjs backup <本地目录> <云端目录id> [--label 名] [--dry-run]

# 校验（对比云端 / 本地相对路径集合）
node tools/wocloud-bulk.mjs verify <本地目录> <云端目录id>

# 清理根级错位残留（默认预演，--yes 执行）
node tools/wocloud-bulk.mjs clean <本地目录> <云端目录id> [--yes]
```

## 过滤规则

- 有 `.git` 的目录 → 只取 `git ls-files`（`.gitignore` 自动生效）
- 无 `.git` → walk，跳过 `.git node_modules __pycache__ .venv` 等
- **凭证硬排除**：`.env* *.pem *.key *.p12 *.pfx id_rsa* *credential* *.secret*`

**`git ls-files` 陷阱**：子目录**没有自己的 `.git`** 时，`git ls-files` 会**向上找到父级仓库**并返回仓库根相对路径，导致复制全部落空。工具已按「只有自带 `.git` 才用 git 模式」处理。

## 实测数据

| 对象 | 规模 | 结果 | 用时 |
|---|---|---|---|
| 知识库目录 | 112 目录 / 552 文件 / 26 MB | 补目录 75 个 **0 失败**；直传 **552/552**；校验仅缺 2 个 0 字节 `.gitkeep` | 补目录 178s + 直传 292s |

**字节级验证**：抽查 3 个文件（含深层路径）SHA-256 与本地完全一致。

**凭证复核**：staging 与最终云端内容均无**私钥 / 云厂商密钥**；含令牌的插件配置已被 `.gitignore` 正确排除。

## 已知限制

- 云盘**不收 0 字节文件**（`.gitkeep` 会 400），verify 时这类缺失属预期
- 服务端 `QueryAllFiles` 单页上限 1000；`ls` 硬编码 100 且**静默截断**（排查时曾误以为根目录只有 87 个文件，实际 285 个）。要完整列表用 `raw QueryAllFiles` 传 `pageSize: 1000`
- `mv` / `rm` 的 `--version` 是整批共用值，批量操作前必须按 `fileVersion` 分组

## 待改进（CLI 侧）

1. `push` 应把建目录失败视为**致命错误**（至少不要静默回退到 `targetId`），否则错位且无告警
2. `CreateDirectory` 失败应按指数退避重试，而不是直接放弃
3. `ls` 应支持分页（或默认拉全），`pageSize: 100` 会静默截断
4. `upload` 遇 0 字节文件应跳过并告警，而非报 400 失败
5. 可考虑把本工具逻辑下沉到 CLI（如 `push --safe` 模式）
