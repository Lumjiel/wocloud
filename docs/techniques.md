## 一、上传

### 1. 文件名预检（P0，已采纳）

**对方**：`validateName()` —— 三类名字**永远不可能成功**，且都用 `NoRetryError` 阻止整轮重试：

| 情况 | 服务端行为（rclone 实测） |
| --- | --- |
| > 100 个字符（rune） | **静默截断** —— 最危险，会变成另一个文件 |
| 含非 BMP 字符（如 😀 U+1F600） | 裸 HTTP 500 |
| 含 BMP emoji 象形符（© ® ™ ❤ ☀ …） | `RSP_CODE 1009 名称中含有非法字符`，整个路径被拒 |

**我们**：无任何预检。超长名静默截断后，事后大小校验还会「通过」（服务器记的就是截断后的文件）。

**落地**：`checkRemoteName()` —— 长度 > 100 **硬拦**（数据安全，无争议）；emoji / 非 BMP **警告不拦**
（rclone 的表按 UCD emoji-data 生成，©® 这类可能误伤，先警告 + 失败时给提示）。

### 2. 空对象检测（P0，已采纳）

**对方**：上传结束若 `fid`/`wcFileId` 为空，直接报错，不把「没有对象的成功」当成功。

**我们**：`resultFid` 为空仍返回 `{ok:true, fid:""}`，批量上传统计里算成功。

**落地**：本次真正提交过分片、结束时仍无 fid → 失败并提示用 `ls` 复核。断点续传「全部已传完」的情况不误报。

### 3. 覆盖写安全（P1，实测后判定「不需要」）

**对方**：`Update()` 先传临时名（`.rclone-tmp-`）→ 旧文件改名备份（`.rclone-old-`）→ 临时名 rename 成正式名 → 删备份。
中途失败时旧文件**始终可读**，最后一步才移交名字。

**我们**：同目录同名直接传。

**2026-10-26 PC 实测结论**：服务端覆盖是**原子的**。64 MB（4 分片）同名上传进行到 65%（前几片已提交）时强杀进程，
旧文件仍然 64 MB 完整可读、SHA256 未变；重传后内容正确。也就是说**最后一步才切换名字**，
不需要在客户端再做「临时名 → 备份 → rename」。

### 4. 失败分类（P1，已采纳）

**对方**：`NoRetryError` 包住「名字非法 / 空间不足 / 鉴权失败」，pacer 立刻收手。
**我们**：`isRetryable()` 拿**错误消息正则**判断：

```js
if (/\b(400|401|403|404|413)\b/.test(msg)) return false;
```

`分片 4/400 失败` 这类消息会被误判成「HTTP 400，不重试」。

**落地**：`isRetryable()` 改成分层判断 —— `err.retryable` 显式标记 → 4 位业务码（1000/1001/1009/2001/9999 不重试）
→ `err.status`（5xx/408/429 重试，其它 4xx 不重试）→ 消息里只认 `HTTP 4xx` 语境。HTTP 错误对象现在都带 `status`。

### 5. 中途 token 失效（P2，记录）

**对方**：上传中撞 `1001` → 刷新 token → **用新 token 重新加密 fileInfo** → 原分片重试一次。
**我们**：`fileInfo` 用上传开始时的 token 派生密钥加密，token 中途刷新会让已加密的 fileInfo 失效。
**风险**：token 有效期 7 天，单文件上传不可能跑 7 天，**实际不会触发**；仅提醒未来做「超长队列常驻」时注意。

### 6. 分片内存（P1，已采纳并实测）

**对方**：固定缓冲池 `concurrency × 最大分片`（8 MiB），生产者顺序读、消费者并发发。
**我们（改前）**：每分片 `Buffer.alloc(16MiB)` × 6 并发，叠加 FormData/fetch 拷贝。
**我们（改后）**：`fs.openAsBlob(localPath)` 只拿文件句柄，每片 `blob.slice(start, end)` 交给 FormData，
undici 按需流式读取；老 Node（<19.8）自动回退 `readSync` 整块路径。

**PC 实测（64MB，4 分片，同网络）**：

| 版本 | 耗时 | RSS 峰值增量 |
| --- | --- | --- |
| 旧（`readSync` + Buffer） | 162.6s | 356 MB |
| 新（`openAsBlob` 切片） | 161.3s | 76 MB |

耗时基本不变，内存降到原来的 ~21%。回归：20MB 双分片上传 + 回下载 SHA256 一致（15/15 通过）。

### 7. 不采纳

- **每次尝试新 uniqueId**：rclone 用来防止重试分片混进废弃会话；我们的断点续传是**故意复用** uniqueId 跨进程续传，两者目标相反。
- **强制 8 MiB 分片**：我们实测 16 MiB 更省请求数，且服务端接受。
- **目录创建后的重查**（rclone 4 次 × 2s）：那是 rclone 自己「建目录后立刻列目录」的最终一致性补偿；我们 `push` 已有 `mkdir` 缓存。

## 二、下载

### 8. 直链 TTL（P1，已采纳）

**对方**：真实有效期 120 分钟且**不随访问滑动**，自己只缓存 **30 分钟**（1/4），宁可多换一次链。
**我们**：进程内按需换链；长任务（`mirror` 几十 GB）里一条链接用到 100+ 分钟才换。
**落地**：`downloadSegmented()` 新增 `linkTtlMs`（默认 25 分钟）。每段开拉前检查，到点主动换链；
并发段同时到点由 `refreshLink()` 单飞合并。不用等到 519 再救，也不用回退整段进度。

### 9. 状态码语义（P0，已一致）

| 码 | 含义 | rclone | 我们 |
| --- | --- | --- | --- |
| 519 | 自然过期 | 换链一次 | ✅ 换链 |
| 403 | 被撤销/无权限 | 换链一次 | ✅ 换链 |
| 518 | URL 被篡改/拼错 | **不换**（换也错） | ✅ 换链（无害，我们从不拼错） |

### 10. 已对齐的下载手法

- **单飞刷新**：32 段同时撞过期只换一次链（rclone 是单对象 `invalidateURL()`；我们是 `refreshing` Promise）
- **探测段 404 瞬时重试**：CDN 突发限流会误报 404，不能直接判死
- **Range 探测拿总大小**：`bytes=0-0` → 206 + `content-range`
- **分段各自退避重试**，失败不整文件重来

### 11. 可选的强校验（P2）

**对方**：下载直链的 **ETag = 内容 MD5**（仅单分片文件；多分片 ETag 带 `-N` 后缀不是内容哈希），
可做 `HEAD` 比对；上传后 60 秒内哈希未稳定，宽限期内不报错。

**我们**：只有大小校验。若要做「内容级校验」，限制条件一样：只对 <16 MiB（单分片）文件有效。

## 三、双方都值得抄的工程细节

| 手法 | 说明 | 我们的状态 |
| --- | --- | --- |
| 控制面节流 `pacer` | 10ms 起、指数退避、上限 2s；批量删/移偶发 500 时有用 | 无（靠业务重试） |
| 空 `familyId` 必须省略 | 传空串服务端回 `9999` | 未做家庭空间，暂无影响 |
| 区域 URL 空值即报错 | 缓存前校验，别拿空串拼 URL | `resolveUploadServer()` 有回退，但没显式判空 |
| 上传前容量/单目录预检 | rclone 用 `QueryCloudUsageInfo` 剩余空间判超限 | 已有 `warnFileLimit()`（只提示） |
| 服务端 5xx 不等于「文件坏了」 | 单分片 500 往往是名字问题，不该无限重试 | `isRetryable` 已把 5xx 归类可重试，靠预检兜 |
